# 著色要保留多少可能性：完整邊界與回填色

2026-10-26。接續[完整消元](four_color_completeness.md)、[RAM索引](four_color_ram_indexes.md)
及[前綴剪枝](four_color_logic_optimization.md)。本次先驗證縮減契約，再將無損的四位元
回填色表示接入[主程式](../scripts/four_color_constraints.py)。所屬研究線見[導覽](four_color_guide.md)。

## 結論與契約

不能用「每點留兩色」或「每張表留前幾列」保證最後能染色。應分開看完整邊界色組，
與該色組下面的內部回填選項。完整邊界關係的資訊要保留；表示方式可以無損壓縮。

| 保留方式 | 一份共同染色／可滿足性 | 全部原解 | 本輪採用 |
| --- | --- | --- | --- |
| 全部有序邊界列，每列全部回填色 | 保持 | 保持 | 原契約 |
| 全部有序邊界列，每列一個合法回填見證 | 保持，但須符合下述完整消元前提 | 一般不保持 | 只做對照實驗 |
| 全部有序邊界列，每列用4-bit mask存全部色 | 保持 | 保持 | 接入主程式 |
| 任意刪除邊界列，只留固定數量或比例 | 一般不保持 | 一般不保持 | 負控制 |

一次消去一點 `x`，先合併所有含 `x` 的因子，令完整有序邊界為 `S`。
對每份邊界配色 `b`，記 `F(b)` 為所有同時滿足這些因子與來源候選域的 `x` 色。
後續因子只需要 `R = {b : F(b) 非空}`。若保留每一個 `b∈R`，並替每列保存任意
`f(b)∈F(b)`，則投影 `R` 不變；全部消元成功後，倒序按同一份實際 `b` 取 `f(b)`，
便可依[原回寫論證](four_color_completeness.md)接回原圖。這不等於提前給原頂點選色。
成立前提是全部含 `x` 的限制已納入、完整接口與字面色框保持，不能遺漏附件或拼接邊際見證。

所以「每個完整邊界一個見證」對求一份解足夠，但會失去其他原解，不適合取代既有
完整fibres證據。對目前一次消去一點、只有四色的引擎，全部色集合可表示為
`mask(b) = Σ(1 << c), c∈F(b)`。例如 `{0,2,3}` 是 `0b1101`；15種非空集合都精確保存。
缺席的邊界列仍表示空fibre，不是未探索；內部只存非零mask。這不是任意多點內部解
都能用4-bit保存的主張。

## 反例：保留231／232列仍可能錯

取五點星形圖：中心 `x` 接四個葉點，葉點互不相鄰。消去中心後，四葉的256份配色
中，只有24份「四色全部出現」不能延伸，故完整關係有232列。

即使保留字典序前231列，只刪掉最後的 `(3,3,3,3)`，外側將四葉都固定為3時，
截斷表就會錯誤判空。但原圖顯然可用中心0、四葉3完成。實驗另外核對保留
1、2、4、8、16、64、128列的七個對照，皆有原圖合法見證而被截斷表拒絕。

更一般地，在支援任意邊界固定色的契約下，每個被刪掉的合法邊界都能成為唯一允許的
外側條件。因此「留多少百分比」不足以保證；若要合併不同邊界，還須另證對所有相關
外側條件等價並保存回寫映射。本輪沒有實作此類合併，也沒有一般免消元保證。

## 實驗與採納

[獨立驗證程式](../scripts/four_color_retention_audit.py)以原邊及固定色的Cartesian枚舉
作小圖oracle，逐份核對原解、全部消元輸入關係的完整連接、非空與空fibres，
再比較原tuple、無損mask、每列最小色、最大色及seed-17選一色五種儲存方式。
所有表示都保留同一有序邊界；另核最小／最大回寫，合計每份有解輸入七次完整回填。

| 小圖覆蓋 | 條件數 | 可解／無解 |
| --- | ---: | ---: |
| 0至5點全部帶標號簡單圖，無固定色 | 1,100 | 1,099／1 |
| 1至3點全部圖的全部非空部分固定色指派 | 1,044 | 820／224 |
| seed-20261026六點圖、非連續ID、固定色及頂點次序 | 96 | 68／28 |
| 合計 | 2,240 | 1,987／253 |

前兩組是明列有限範圍的窮盡；第三組只有指定隨機樣本。未假設平面性，包含K₅無解控制。
全部小圖核對13,909次合法回填；不是只比對SAT／UNSAT標籤。

原四十份凍結輸入另核27可解／13無解，完成189次回填，逐原邊及固定色驗證。
這批完整紀錄合計149,040個邊界列、201,747個回填色選項：單見證法只保留149,040個色，
mask仍保留全部201,747個選項。原獨立參考覆蓋仍為四份全原邊解、二十四份結構全域投影、
十二份指定合法見證或凍結窮盡無解參考；沒有擴大成全部隨機圖解枚舉。

| 四十例回填map的估計物件體積加總 | bytes |
| --- | ---: |
| 原完整色tuple | 30,351,392 |
| 無損4-bit mask | 21,583,496 |
| 每列只留一色，三種選法均同 | 21,583,496 |

mask在此批比原tuple少28.89%，並與只留一色相同。這是Python 3.14的`sys.getsizeof`
遞迴估算，逐個map計共享物件一次，再將各案例加總；只量實驗重建的回填map，
不含完整公開紀錄、因子、快取或解譯器，**不是程序RSS，也不是整體記憶體降幅**。
Python整數物件並非只占4個實體bit。小圖中mask和單見證的估計體積也可能因共享
小整數數量而有少量差異，不能宣稱所有輸入逐byte相同。

基於這個結果，主程式採無損mask儲存內部回填選項；所有公開列、預覽及回寫事件
仍展開為原先排序的完整色列表。工作與儲存列數預算、最後才回寫的流程保持。
這項改動沒有減少邊界列，不能解除隨接口寬度增長的指數瓶頸。
