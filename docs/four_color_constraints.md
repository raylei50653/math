## 使用

```bash
python3 scripts/four_color_lab.py constraint-demo
python3 scripts/four_color_lab.py solve graph.json --engine constraints --json result.json --html replay.html
python3 scripts/four_color_lab.py solve graph.json --engine constraints --edges-only
python3 scripts/four_color_lab.py solve graph.json --engine constraints --intersections
```

求解器只需 Python 標準函式庫；圖的 JSON 格式與既有實驗相同。
播放器顯示「傳播／消元」和「倒序回寫」兩階段，可直接跳到回寫。
原有固定色始終保留；所有其他點即使只剩唯一候選色，也要等到全部消元成功後才寫入。
消去一個點不會刪改輸入原圖，只是將它的影響換成一份關係表。

## 保留共同可能性

每點各有非空候選集合，不表示這些選項能共同成立。例如三角形三點都只剩
`{1,2}`：每點有兩個選項，每條邊也有合法配對，但三點沒有共同異色的選擇。

`triangle_joint_conflict` 用一張五點平面圖展示這件事：三角形的三點各接到另外
兩個互不相鄰的點，後兩點固定成色 3、4。矛盾來自這份固定色條件；解除固定色後，
同一圖仍可四色染色。對照案例為 `triangle_joint_free`。

因此這個引擎保存有序邊界的**整列顏色組合**，不把它拆成各點互相獨立的候選集合。
畫面中的表格列數是可延伸的邊界組合數，不是完整原圖染色數；每列另記被消去點的
全部可用色，以供最後回填。

## 記錄哪些子構造

初始表庫保留字面色號 0–3，沒有獨立換色框：

| 子構造 | 精確局部條件 | 合法列數 |
| --- | --- | ---: |
| 一條邊 | 兩端不同色 | 12 |
| 三角形 | 三點兩兩異色 | 24 |
| K₄ | 四點兩兩異色 | 24 |

同一種表可映射到不同原頂點次序後重用；表本身不可變，固定色造成的過濾只作用於
當次實例。程式先使用全部 K₄，再使用未被 K₄ 包含的三角形，最後補未覆蓋的邊。
所有原邊都被某個約束涵蓋；較大團不會漏掉邊。`--edges-only` 保留逐邊表作對照。

此外，每次消元都新增一份當前子問題的邊界表。完整執行 JSON 記錄其原頂點、
有序接口、全部合法列、每列的回填色，以及參與的原邊。
若先前傳播已受其他約束影響，該表也會記錄當時的 `source_domains` 和
`input_relations`。**只看 `source_edges` 不足以重建這份帶上下文的表**；
不可把它當成任意外側都能沿用的獨立子圖定理。
在記錄的候選域乘積內，沒有出現在合法列中的邊界組合明確表示空 fibre；
不是未計算或可以任意填補的列。

上述三種精確模板直接建立初始因子；自動產生的消元表用於本次後續傳播、回填及重播。
另有[已知衝突表庫](four_color_conflicts.md)，記錄完整四葉星形投影及有條件的空關係，
只有核對同一原子圖和目前候選域後才採用。沒有聲稱已完成任意子圖的同構辨識或跨圖快取。

## 三個操作與正確性

1. **傳播**：刪除關係表中與當前候選集合不相容的列，再用各欄投影收緊候選集合，
   反覆執行至穩定。這只刪去無局部支持的可能性，不把某個候選色直接寫入原圖。
2. **消元**：選點 x，合併所有含 x 的關係，投影掉 x；保存每個邊界列對應的全部 x 色。
   選點優先讓新增加的約束連接最少（min-fill），再比較接口大小及輸入頂點次序。
3. **回填**：全部消元成功後倒序處理；依已經確定的整個邊界列查表，再選一個支援色。
   最後逐原邊、逐固定色驗證完整輸出。

設含 x 的約束為 B₁,…,Bₖ，所有其他約束為 Q。替換表定義為
`R(y) = 存在 x，使 B₁(x,y) ∧ … ∧ Bₖ(x,y)`。
所以 `Q ∧ R` 與消元前的可滿足性相同。倒序已確定 y 時，保存的支援集合恰好提供
一個共同相容的 x；這個保證逐步接回全部原約束，而不是任選各點的邊際可能色。
傳播也保留每一份原本合法的完整解，因此不破壞此等價性。

只做逐邊候選色傳播通常會停住；此實作仍要保存更大接口的聯合關係，才能完成判定。
沒有使用回溯試色，但表格大小最壞會隨接口寬度指數成長。省下回退，不等於省下所有計算。

## 狀態、預算與比較方式

`colored` 表示已完成一致回填並驗證；`unsatisfiable` 表示某份精確約束關係已排空，
有固定色時只判定該固定色無延伸；`limit` 表示預算耗盡，不能當成無解。
在失敗或超限結果中，沒有新增回寫顏色。

`--max-checks` 限制候選組合檢查加上關係列過濾／查表的總計；另有限制累積新表列數的
防爆上限 `min(max_checks, 100000)`。完整證書快照的累積列數也受此上限約束。
大量比較使用 `record_relations=False`，省略公開輸入表快照，仍保存內部回填表；
命令列預設記錄完整表，因此在較大的圖上可能先遇到證書儲存上限。
`--trace-limit` 只限制事件記錄，不影響判定。圖結構搜尋及最後驗證不算關係檢查。
子構造模板的重用次數與消元產生的關係數分開計算，不把模板取用稱為整圖快取命中。

同批樣本比較命令：

```bash
uv run --with-requirements requirements.txt python scripts/four_color_lab.py constraint-experiment --count 100 --vertices 30 --seed 0
python3 -m unittest discover -s tools/tests -p 'test_four_color*.py' -v
```

比較以相同圖的 SHA-256 對齊，分為只用邊表、加入子構造、既有 DSATUR 三種方法。
樣本由面內插點及合法翻邊生成，非均勻抽樣；每張另外驗證平面性。
約束法的列檢查數和試色法的填色次數是不同工作單位，不能直接相除稱為加速倍數。
計時是本機單次實測，約束兩模式交替執行順序；不代表所有平面圖的速度保證。

## 實際結果與驗證

本節保留加入已知衝突辨識器之前的實測；新版本預設可能更早命中已登記子型，
不能把下列消元數或歷史計時當成新預設模式的結果。

在五點 `triangle_joint_conflict` 上，只用邊表需 **273 次檢查、2 次消元**才判定
固定色無延伸；加入子構造後 **48 次檢查、0 次消元**即可判定。兩者均未新增回寫顏色。
同一張圖解除固定色後，兩種模式都成功完成回填。

同批 100 張、各 30 點、seed 0–99 的平面圖，每張約束法至多 1,000,000 次檢查，
保存列數上限如上，結果如下：

| 方法 | 成功／超限 | 總檢查次數 | 最大作用中表列數 | 本機總秒數 |
| --- | ---: | ---: | ---: | ---: |
| 只用邊表 | 89／11 | 42,145,824 | 20,172 | 15.84 |
| 邊＋三角形／K₄ | 95／5 | 28,290,656 | 4,680 | 9.54 |
| DSATUR＋強迫 | 100／0 | 不同計數單位 | 不使用關係表 | 0.29 |

兩種約束法皆成功的同一組 **89 張圖**，檢查次數由 31,145,824 降為 18,708,308，
減少約 **39.9%**；耗時由 11.77 秒降為 6.49 秒。
整批累積產生的邊界表列數由 1,965,397 降為 367,132；這是跨圖累計，
與表中「單次求解最大同時作用中的總列數」不同，也不是實際記憶體 bytes。
兩種約束法最大接口均為 8 點；即使最後需要回寫的點不多，中途仍可能形成大表。

這批圖原有 DSATUR 仍較快；它共做 3,856 次填色與 257 次回退。
約束法成功案例均沒有提前試色或回退，超限案例也沒有新增回寫。
子構造已改善這份關係表實作，但沒有建立普遍優於搜尋的效能結論。

驗證共 **25 項測試**通過：既有引擎 13 項，加上新引擎 12 項。
新引擎對全部 1,024 張五點圖、子構造開／關兩模式，共 2,048 次與獨立枚舉比對；
另核對固定色、每份完整聯合投影、所有合法染色的保留、反向共同見證、非 K₅ 無解例、
無提前回寫及資源限制。全部成功樣本都逐原邊驗證。
新播放器的 12 組實際記錄與空圖、零事件、超限、混合引擎已經 Chromium 操作檢查。

正常執行與 `PYTHONHASHSEED=17` 的案例輸出逐位元組相同。
最終來源重跑 100 圖比較，300 份模式結果及工作計數一致；計時另行保存。
比較 JSON 記錄圖的 SHA-256、執行版本與四份產生器來源 hash。
以上歷史比較使用的四份來源已逐 hash 核對並保存在
[`baseline-source/`](../artifacts/four_color_constraints/baseline-source/)，
可與後續 C₅ 實作區分；本節數字沒有改寫成新版本的計時。
