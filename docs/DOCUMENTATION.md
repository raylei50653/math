# 文件維護規則

更新：2026-10-30。本規則管理功能入口、活躍結論及完整研究檔的短生命週期；不改變數學結論。

## 按主題漸進披露

先依要完成的工作選入口：接續研究、執行工具、驗證證據、調用既有成果、查閱封存。
[研究總覽](research_overview.md)解釋問題與方法的關係，[HANDOFF](HANDOFF.md)提供功能入口及進行中標記。
目前採納的結論、適用範圍、證據層與 OPEN 由[活躍結論](research/CONCLUSIONS.md)統一維護；
第一個接續工作與驗收由[4CT 研究契約](research/4ct_guide.md#精確消元主線的研究契約)維護。

```text
工作入口 → 活躍結論 / 研究契約 / 操作導覽 → 當輪所需完整來源 → Lean / scripts / artifacts / audits
```

活躍文件須足以支持研究判斷：說清問題、已有能力、關鍵前提、尚缺義務及證據入口。
不為減少字數刪除會影響方法選擇的限定，也不要求日常先讀完整歷史。
完整證明、反例、全部 fibres、witnesses、驗證數字及失敗控制保存在原報告與證據中。
定義與操作規格有持續使用價值時可保留為穩定參考；不把所有來源都改寫進活躍文件。

每個採納結論有一個目前維護位置；專題來源承擔完整論證，封存目錄不另作當前裁決。
未提升到活躍結論的歷史引理仍可依完整前提引用，不能因未列入摘要就判為失效。
共用引理引用原論證，不在多條研究線複製證明；導航樹不等於數學證明 DAG。

| [研究契約](research/4ct_guide.md#精確消元主線的研究契約) | 研究對象、第一個工作與驗收 | 接續工作或驗收改變 |
| 工具／驗證導覽、穩定接口規格 | 可用能力、操作方法、定義與限制 | 能力、接口或操作契約改變 |
| `docs/research/work/` | 尚在核對、整合中的完整研究檔 | 當輪工作；完成整合後退出此處 |
| `docs/archive/reports/` | 完整前提、論證、反例、證書與當輪停止點 | 整合後封存；有錯誤才追加短更正或後續提示 |
| [STATUS](STATUS.md)／[完整目錄](archive/catalog.md) | 功能查找入口／全部文件直接索引 | 路徑或新增來源改變；不逐輪寫成果長描述 |
| `docs/history/` | 研究及發布的當輪紀錄 | 需要保留決策、驗證或發布時；不作目前排程 |
| `docs/sources/`／`paper/` | 匯入原稿／特定論文敘事 | 保留來源版本／論文整合；不作目前研究入口 |

### 完整研究檔的短生命週期

預設以**一輪研究**為生命週期，不讓已完成的實驗報告長期留在活躍工作區。
一輪內可以有必要的補證與獨立核對，不設以時間或文件數決定完成的期限。

1. 在工作檔記錄對象、前提、候選結論、完整推理及實際證據；未驗證者明示候選。
2. 核對結果與原始資料，區分紙證、外部定理、Python、Lean 及未重播範圍。
3. 將影響目前採納依據的結論、限制與 OPEN 整合到 CONCLUSIONS；若改變接續工作，再更新研究契約。
4. 完整研究檔移入 `archive/reports/`，補直接索引及當前結論到來源的連結；原證據不重生成。
5. 封存後不逐輪回改其「下一步／未解」；新進展在活躍文件更新，必要時只於原頁首補後續提示。

未完成推理、來源未核對或證據尚缺時，可暫留工作檔並明列缺項；本輪明確無增益或失敗也可
作為負結果整合後封存。封存不表示 CLOSED；未採納的猜測不能因搬移或到期升格為結論。
已完成的完整報告可立即封存，即使父命題仍 OPEN。後續引用時沿活躍結論查最新裁決，沿原報告查證明。

## 研究線頁首導讀與生命週期

HANDOFF 上限 30 行，以 `- [名稱](相對路徑_guide.md)` 列功能導覽，進行中才加 `#進行中`。
無 tag 不代表完成；列表順序不作優先級。進行中狀態只在 HANDOFF 維護。

HANDOFF 所列導覽在標題後以 `## 研究概況與閱讀入口` 提供導讀；既有 `## 最新進度` 仍相容。
區塊在前 12 行開始，整節不超過 40 行，包含讀者說明及至少一個本地 Markdown 來源或本頁章節連結。
導讀回答「這裡能幫我做什麼、已有能力的界線、接著去哪裡」，不逐輪另存採納結論或里程碑。
工具、驗證及封存導覽依功能維護，不需要虛構正在執行的下一步。

舊研究線導覽已移入封存，供查既有分支、來源與證據；不要求每輪同步全部舊 guide。
[舊生命週期試點](history/2026-10-13-research-line-lifecycle.md)保留當時的卡片規格與成本估算，
目前活躍結論與短週期採本規則。結構檢查不能判斷來源是否足以支持當前研究判斷。

## 每次研究更新

先處理結果與證據，再整合目前結論，最後封存與維護連結。純重播只記驗證範圍，不假造進度。
每輪不必改動所有活躍文件；研究結果未影響目前採納結論、下一步或操作能力時，保留在完整來源即可。

### 修改範圍與擴大觸發

| 變動 | 必要維護 |
| --- | --- |
| 新結果、失敗控制或補證 | 完整工作檔與原證據；核對 CONCLUSIONS 的相關採納項，有變才更新 |
| 下一個工作或驗收改變 | 研究契約對應章節 |
| 實作能力、接口或重播方法改變 | 相應工具／驗證導覽或穩定規格 |
| 影響直接父題、既有採納前提或 consumers | 對回原假設核對受影響者；只沿實際語義影響向上擴大 |
| 純封存、搬移或新增來源 | 目錄、相對連結及必要相容入口，不更新研究成果日期 |

沒有影響就停止傳播，不因文件位置或共同 guide 而全面重審研究線。
CONCLUSIONS 不收逐輪實驗日誌或所有局部引理；保留對接續工作有用的結論與必要完整限定。

### 真正收尾與反向核對

Closure 指具名數學範圍內的證明義務已完整解決，或經正式裁決終止／取代。
必須明列命題、圖類與量詞、全部假設、定義內分支覆蓋、證據層及未涵蓋範圍；不足時保持 OPEN。
封存、commit、checker PASS、有限零殘留及子分支完成，都不自行決定父題 closure。

確認 closure scope 後核對直接父題與 consumers；利用 DocGraph 已宣告反向邊、Markdown 引用及普通檔案搜尋
找候選，再逐份對回前提。零 metadata 邊不能當作沒有使用者。只在語義影響更高層時繼續往上核對。
在原研究紀錄簡記更新、核對未變與剩餘 OPEN，不新增第二套狀態總帳。

反例、重大前提錯誤、證據失效或 supersession 若影響已採納結論，立即更新 CONCLUSIONS，
核對直接使用者並連到更正來源。原報告可加有日期的更正／後續提示，不覆寫凍結證書或歷史失敗。
封存導讀整理已知更正與後續關係，不接管目前採納裁決。

## 專題報告必要資訊

完整研究檔須能獨立查證，章節依論證需要安排；不要求一命題一檔或一次改寫所有舊報告。

- 日期、來源／依賴、適用圖類、量詞及全部前提。
- 精確結論、反例或無增益範圍，以及尚缺的義務；候選與已核實分開。
- 紙證、外部定理、Python 固定域、Lean 普通證明與 `native_decide` 分別標示。
- 具名 theorem／script／artifact、重播命令、原資料與 SHA；實際重跑及沿用證據分開。
- 整合到哪個活躍結論或接續契約；若只作歷史控制，明示不影響目前採納依據。

固定 q 不提升為完整 Σ，list 介面不提升為 disk 實現，有限模板不提升為任意大小定理。
獨立前提、完整 fibres 與關鍵反控制不為減少文件數而刪除；`limit` 仍是未定。

## 信任範圍與工作約定

工作目錄為專案根目錄。接手先讀活躍結論、研究契約及 `git status`，再展開當輪來源。

- Lean 普通證明以具名 theorem 與 `#print axioms` 為準；`native_decide` 另含 native compiler 信任。
- 紙面拓撲與 Python 固定域控制分開；`lake build` 不表示新紙面 minor 或 disk 論證已形式化。
- 完整有序關係、全部空／非空 fibres、共同色框及同一見證為組合基線；最後倒序回寫。
- Kempe 交換後重算實際連通分量，保留原 O 及全部遠端附件；端點 marginals 不能拼接見證。
- 一般 planar C5 與 disk 外邊界分開；一般 BAD 構造不是 BAD disk。不以待證 4CT 作搜尋 oracle。
- 沿用具名 witnesses／證書，不自動重跑大枚舉，不重生成歷史證據。未要求不 commit／push。
- document-first；只有使用者 `/graphify` 或文件無法解釋跨檔關係時才用 Graphify。
- Lean／mathlib 鎖定 `v4.34.0-rc2`，不自動 `lake update`；Python 使用專案依賴環境。

歷史命令可能指向舊路徑、釘選 Git 基線或排他建立的輸出，不將產生器當只讀 checker。
[遷移保存說明](archive/migration-2026-10-30/README.md)提供搬移前原始 Markdown 與重播界線。

## DocGraph metadata

既有 stable `id` 與 `family`、`requires`、`derives_from`、`related` 隨來源保留，不因搬目錄而重命名。
只宣告有實際語義的關係，不把連結或目錄樹當數學蘊涵；不要求為封存全面補 metadata。
[DocGraph](../tools/docgraph/README.md)的反向邊與 closure 只涵蓋已宣告 metadata，圖不承擔目前結論或排程。

## 檢查與搬移

```bash
python3 scripts/check_docs.py
python3 -m unittest discover -s tools/tests -p test_check_docs.py
python3 tools/docgraph --include 'docs/**/*.md' check
python3 tools/docgraph check
git diff --check
```

連結檢查涵蓋 README、docs、paper 及 artifacts Markdown 的本地路徑與章節錨點。
STATUS 可把完整直接索引交由明確連入的 `catalog.md` 承擔；未連入目錄及一般報告不提供間接索引覆蓋。
HANDOFF 與所列功能導覽仍檢查格式及導讀。外部網址不連線檢查，結構通過不表示數學結論正確。
正式 docs 與全工作樹 DocGraph 分別報告；保留快照重複 ID 的診斷，不刪歷史來製造全域 PASS。
純文件重構不要求研究枚舉、產物 rebuild 或 Lean build；checker 改動則跑相關測試。

本次搬移保留原檔名、stable ID 與全部完整來源；相對連結可維護，原 bytes 另以可核對快照保存。
舊 STATUS 章節在[封存目錄](archive/catalog.md)保存，根 STATUS 保留相容入口；新引用直達來源。
凍結 publication、匯入原稿、JSON 證書與具名歷史程式不作全域路徑替換。
