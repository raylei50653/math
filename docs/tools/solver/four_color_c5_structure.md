# 從五環結構推出自約束

2026-10-25。接續[C₅ 查表與傳播](four_color_c5.md)。同一個原五環可以用完整表查詢，
也可以沿原邊直接推導限制。這裡先說明能看懂原因的結構規則，再給一般候選域的精確推導。
兩種方式都保留原頂點次序與字面色框，只縮限候選域，等全部消元成功後才倒序寫色。

後續[局部資訊外推核對](four_color_local_information.md)把推導擴為任意長度環，保留首末
共同色對及完整回填；也用星／輪原圖核對全部三點投影仍不足。一般環 API 為獨立模組，
下述命令列找環入口仍是 C₅。

```bash
# 啟用 C₅ 時，預設用結構推導：
python3 scripts/four_color_lab.py solve graph.json --engine constraints --c5 --c5-method structure --json structure.json
# 同一輸入改用 240 列索引查表：
python3 scripts/four_color_lab.py solve graph.json --engine constraints --c5 --c5-method table --json table.json
```

`--c5-local` 決定如何找環，`--c5-method` 決定找到環後如何推出限制；兩個選擇彼此獨立。
命令列啟用 C₅ 時預設 `structure`；Python 的 `solve_constraints()` 為保持既有呼叫者行為，
`c5_method` 參數預設仍為 `table`，需要結構法時明確傳入 `c5_method="structure"`。
下述推論只需確認原五環的五條邊；找環器目前仍使用既有的無弦五環規則。
色號以下使用 JSON 的 0–3。

## 兩色奇環：繞一圈必衝突

設原環為 `v₀–v₁–v₂–v₃–v₄–v₀`，目前候選域為 `D₀,…,D₄`。
若所有候選域都包含在同一個至多兩色的集合 `P` 中，環上只能使用這兩色。
沿每條邊都必須交替；走完奇數條邊，閉合邊的兩端便同色。因此沒有合法延伸。

這直接解釋 `c5_two_colors` 衝突，不需要先看 240 列為什麼全部被刪光。
它否定的是這份候選域條件；裸五環本身可三染。

## 唯一逃逸點：必須跳出共同兩色

若除 `vⱼ` 外的四點都只能使用同一個兩色集合 `P`，那麼 `vⱼ` 必須使用 `P` 以外的色：

```text
對所有 i ≠ j，Dᵢ ⊆ P，|P| = 2
                    ⇒ Dⱼ ← Dⱼ \ P
```

理由是：假如 `vⱼ` 也選了 `P` 中的色，就回到上面的兩色奇環矛盾。
因此每個被刪去的候選都有明確反證，不是直接猜一個顏色填入。

例如 `D₀={0,1,2}`，其餘四點皆為 `{0,1}`，便推出 `D₀={2}`。
環本身恰有兩個完整色組 `(2,0,1,0,1)`、`(2,1,0,1,0)`。
一般情況下，`Dⱼ \ P` 非空只是必要條件；其餘點仍可能彼此不相容，
原圖外側也可能再排除剩餘選項，所以不能由「有逃逸色」直接宣布整圖可延伸。

## 雙中心五環：兩中心被迫同色

設兩個不同原頂點 `h、k` 都鄰接五環的全部五點。
若 `h、k` 使用不同色，環上每點都必須避開這兩色，於是只剩另外兩色，與奇環矛盾。
所以任何完整四色染色都滿足：

```text
color(h) = color(k)
```

這是從十五條實際原邊推出的兩點自約束。若兩中心已固定為不同色，就立即矛盾；
若候選域不同，至少可推出兩中心都只能保留共同候選色。

`structure` 模式實際把這個結果導入求解器：對同一原五環的每對共同中心，建立二元等色因子
`{(0,0),(1,1),(2,2),(3,3)}`，規則 ID 為 `c5_hub_equality`。
原來十五條邊已經蘊含這份限制；顯式加入後，傳播及消元可以直接使用兩中心的聯合關係。
所有原邊與其他約束因子繼續參與同一份求解，最後仍核對原圖及輸入固定色。

記錄中的 `self_constraints` 保留實際原五環、兩中心及十五條來源原邊；
事件以 `kind=structural_constraint` 及規則 ID 標示推導。
等色因子會在消元的因子圖連起兩中心；原輸入圖沒有新增一條邊，
也沒有把「兩端異色」的原邊語義改成等色。
這個二元因子可能改變消元次序與接口寬度，實際成本須另行比較，沒有必然加速或寬度不變的保證。
`table` 模式保留原有五環查表傳播，不加入這份額外等色因子。

對**沒有額外邊、固定色或外側限制的裸五角雙錐**，這份兩中心投影恰為
`{(0,0),(1,1),(2,2),(3,3)}`：給兩中心任意同一色，環仍有三色可用，能完成染色。
有額外上下文時，等色仍是必要條件，但四個等色列未必全部可延伸，甚至可能全部為空。
不能只憑這個等式取代同一原圖其餘約束。

## 一般候選域：切開環，雙向傳播再閉合

前三條規則給出短證明；一般 `D₀,…,D₄` 則用路徑結構精確計算，無須保存或查詢 240 列。
暫把 `v₀` 的色記為錨點 `a ∈ D₀`；這只是局部關係的分類，不向原圖寫色。

先沿 `v₀→v₄` 計算前向支援，再由閉合邊 `v₄v₀` 沿反方向計算後向支援：

```text
F₀ᵃ = {a}
Fᵢᵃ = {c ∈ Dᵢ : 存在 b ∈ Fᵢ₋₁ᵃ，b ≠ c}           (i = 1,…,4)

B₄ᵃ = D₄ \ {a}
Bᵢᵃ = {c ∈ Dᵢ : 存在 d ∈ Bᵢ₊₁ᵃ，c ≠ d}           (i = 3,…,0)

Sᵢ = 所有 a ∈ D₀ 的 (Fᵢᵃ ∩ Bᵢᵃ) 的聯集
```

`Fᵢᵃ` 證明左半路徑可到達色 `c`，`Bᵢᵃ` 證明右半路徑能從同一色 `c` 回到錨點 `a`。
兩半路徑的內部互不相交，端點一致便能接成完整五環染色。
反過來，每份合法環染色也同時提供這兩份路徑見證。
因此 `Sᵢ` **恰好是這個五環在目前候選域下有完整局部支援的色**，不是近似篩選。

合法完整色組數也能沿路累加：

```text
p₀ᵃ(c) = 1（c=a 時），否則為 0
pᵢᵃ(c) = 1[c ∈ Dᵢ] × Σ(b≠c) pᵢ₋₁ᵃ(b)
N = Σ(a∈D₀) Σ(c∈D₄ 且 c≠a) p₄ᵃ(c)
```

`N=0` 便是局部空關係；非零時將 `Dᵢ` 收緊為 `Sᵢ`。
每個錨點只沿五條原邊處理四種字面色，沒有先枚舉全部五點色組。
若需要展示完整局部見證，可按同一條路徑的合法轉移重建色組。

## 局部精確與整圖判定的界線

結構法和查表法應得到完全相同的局部支援集合及合法列數；差別是推導方式。
兩個不同位置的支援色可能來自不同完整環染色，不能獨立任選後當成一份共同見證。
多個子圖也必須保留同一原圖、同一有序接口與同一字面色框，接受共同約束。

環上的一般推導輸出精確局部支援；雙中心規則另保留顯式二元等色關係。
沒有聲稱只靠單點候選域就保留全部跨點相關性。
完整整圖染色仍由原邊因子、這些結構因子、既有聯合傳播、消元及最後逐原邊驗證保證；
候選域被外側縮限時，也要保留來源，不能把當時的空關係移植到任意其他外側。
這項演算法改動不啟動 P1–P4，也不改變 C₅ 來源覆蓋的 OPEN 邊界。
