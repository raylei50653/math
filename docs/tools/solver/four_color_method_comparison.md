# 四色求解方案橫向比較：適用條件、成本與退步例

2026-10-27。核對目前工作樹及既有凍結證據；所屬研究線見[四色導覽](../four_color_guide.md)。
本報告只綜合各題結果，不調整參數或預設；各方案的完整契約與歷史量測仍由所引專題負責。
適用輸入為有限簡單無向原圖、字面色號0–3與指定固定色；部分原型另接受候選域。
後續[數學分析與新候選](four_color_mathematical_optimization.md)推導按需mask join、
外側域簽章及局部成本界；已有獨立核對，尚未接入主引擎。

**目前沒有單一方案全面勝出。** 只求一份染色，既有DSATUR是已測自由小圖的強基準；
要完整fibres與最後共同回填，使用完整消元。主引擎內的索引、prefix與delta有有限收益，
靜態切區、更多推理或完整支援差量都可能增加成本。按需接口的BFS掃描在另一批格圖
節省大量實際訊息，但仍有退步，尚未取代主引擎或原型預設。

## 如何讀這份比較

| 比較軸 | 必須分清的內容 |
| --- | --- |
| 求解目標 | 找一份共同解、表示全部解、列出全部fibres是不同輸出要求。完整關係可隱式保存，已查快取本身不等於完整關係。 |
| 證據口徑 | 本輪現場重跑另列；下列歷史數字只在同列的樣本、版本、選項與預算內比較。 |
| 工作與速度 | 試色、關係檢查、按需查詢的checks不同；較少消元／接口／訊息不直接等於較短牆鐘。 |
| 儲存與記憶體 | 累計表列、回填map估算、緊湊JSON與程序RSS分別列出，不能互換。 |
| 預算與完成 | `colored`已核原邊／固定色；`unsatisfiable`是精確判否，有固定色時只否定其延伸；`limit`未判定，搜尋關閉回退的`stuck`亦未判定。 |
| 同一見證 | 保留原點身份、完整有序接口與同一色框；所有孩子須接同一父袋列，不能拼接各自可行的邊際見證。 |

無資源限制下的完整搜尋、完整消元與符合樹形契約的按需查詢，都能精確處理有限輸入。
這不給出固定資源內一般效率，也不補上平面圖必有四色解的存在性證明。
詳見[完備性](four_color_completeness.md)與[數學模型及形式化邊界](four_color_mathematical_model.md)。

不由檢查數推速度比例，也不把當時量測當作目前所有選項全開的結果。

## 加強推理：何時值得多算

| 方案 | 主要適用條件 | 增加成本／仍有缺口 | 既有比較與使用入口 |
| --- | --- | --- | --- |
| C₅查表／結構支援 | 五環候選域受限，尤其雙中心使環只剩同一兩色。 | 裸四色自由圖沒有單點色可刪；找環與查詢可能成為純額外成本。結構等色因子也會改變次序／接口。 | 歷史table模式100自由圖9.596→9.786秒；相容固定組0.875→1.115秒，即使額外刪302色仍較慢。見[C₅](four_color_c5.md)。 |
| 局部C₅掃描 | 先快速取得五度點鄰域中的可用五環。 | 有意漏找其他環；掃描快不代表整體快，既有兩次量測找環只占全程0.75%／6.44%。 | `--c5-local`與完整`--c5`擇一。啟用後CLI預設`structure`，API預設`table`；不是C₅功能預設開啟。 |
| 完整共同接口交集 | 相交因子共享至少兩點，需傳遞整列等色／互斥條件。 | 兩兩一致不保證整體可解；刪少量列仍可能不減邊界枚舉乘積，投影重查反而較貴。 | 初版30自由圖共同成功27例checks 7,119,068→11,451,922，2.399→4.495秒；矛盾控制可5→0消元。見[交集](four_color_intersections.md)。 |
| 交集＋原環閉合 | 長鏈、長奇環、跨區限制需要同一首點色的閉合支援。 | 有找環／閉合成本；有界基本環不等於全部簡單環。 | 同36例11份無解條件矛盾前總消元497／125／0，依序為原模式／交集／再加原環。見[共同傳播](four_color_combined_cycles.md)。 |
| 共同中心條件接口 | 同一中心色限制環上多點，三色中心＋奇環特別有效。 | 條件搜尋、計數、冗餘接口及後續交集都要付費；一律新增投影的原型曾使14份可解例超限。 | 40例十二點例8→0消元，九點仍4次；以完整蘊含檢查省略27,763份冗餘接口。見[條件接口](four_color_cycle_contexts.md)。 |
| 部分輻條搜尋 | 補鄰域模式漏掉的跨區中心／原環條件。 | 搜尋更多構型會大量增加工作；有128構型與搜尋步數限制。 | 歷史40例17可解／13無解／10超限；九點4→0消元。後續流程優化已改善同批成本，歷史數字不混排名。見[部分輻條](four_color_partial_spokes.md)。 |
| 九點自動找型 | 原圖包含21條必要原邊的具名構型，直接加入三元全等關係。 | 找型成本、去重與提交因子成本；不保證其他構型，也不保證外側附件相容。 | 30條件皆完成，九點異色固定4→0消元；未固定主例找型1,831步。見[九點主傳播](four_color_joint_propagation.md)。 |
| 完整共同一致性 | 對同一點全部相交因子查共同支援，彌補一般局部一致性的不足。 | 查詢scope可能涵蓋全圖；額外預算預設200,000，用盡只跳過可選推理，主預算用盡仍`limit`。 | `--joint-consistency`；未完成查詢不提交部分支援，見[約束契約](four_color_constraints.md)。 |
| 三色等色類閉包 | 共同三色域內的共邊雙三角能反覆推出等色，再由共同鄰點排色。 | 不含相應結構時只有掃描成本；不是一般判定完備規則。 | 14點固定色整次455,489→6,648 checks，7次合併與2次三色排除；納入共同一致性模式。見[歸一化](four_color_logic_optimization.md)。 |
| 共同色群歸一化 | 全部候選域與全部因子有同一換色不變群，難查詢可只查代表並完整還原。 | 預檢、群認證、重啟與還原都計費；固定色／非對稱表限制可用群。單查詢較省仍可能做更多查詢。 | 14點裸圖單查詢147,961→20,576，但整次2,282,403→2,282,555；只在共同一致性中自動使用。見同份[報告](four_color_logic_optimization.md)。 |

以上推理選項均可選；共同條件接口需要交集與原環，九點找型可以獨立啟用。
局部規則提前找到矛盾的價值，與整體求解加速分開評估；沒有命中也不撤回完整消元責任。

## 不加新推理：索引、枚舉與完整儲存

| 方案 | 用什麼換什麼 | 有利條件與退步特例 | 證據與現況 |
| --- | --- | --- | --- |
| 流程增量快取＋完整因子起點 | 避免未變查詢重做，從一張完整因子的全部列枚舉剩餘座標。 | 重複交集／笛卡兒候選為瓶頸時有利；完成更多消元也可能增加後續工作。 | 歷史40例84,859,273→16,934,922 checks，10→1超限；最後一例受十萬證書列限制。已納入主程式，見[流程優化](four_color_flow_optimization.md)。 |
| RAM完整接口索引 | 多存完整投影、原列分組與配對索引，換取重用。 | 大表／多次同接口查詢較有利；6份快判否例多0.1–0.4ms。身份／revision／欄序變更須失效。 | 同40例15.27→12.82秒，求解後峰值103.6→106.2 MiB；`--interface-cache`需交集。見[RAM索引](four_color_ram_indexes.md)。 |
| anchor枚舉 | 原完整因子起點加全部延伸，葉端核其餘因子。 | 易延伸的小桶可避免額外前綴管理；大部分無效候選可能較晚才被否定。 | 主引擎預設`--bucket-method anchor`。 |
| prefix剪枝 | 因子最後座標已補齊就核完整關係，失敗跳過不能修復的後綴。 | 因子能早拒絕時有利；5／40例checks略增，包含等色鏈重疊與98點環控制。 | 同40例11,968,026→10,433,208 checks；22改善／13同／5增。見[前綴剪枝](four_color_logic_optimization.md)。 |
| 提高完整表／證書容量 | 允許更多儲存，解除人工列數上限。 | 工作量可接受但完整紀錄略超上限時有用；不會減少運算，也不是預配置RAM。 | 100點例需108,004列；百萬容量使同40例全完成。與可重算快取容量不同，見[儲存容量](four_color_memory_optimization.md)。 |
| 無損4-bit回填色 | 每完整邊界列以mask保存全部四色支援，公開紀錄仍展開。 | 單點消元適用；不減完整邊界列，不解除接口指數瓶頸。 | 回填map估算少28.89%，非RSS；已納入主程式。見[可能性保留](four_color_retention.md)。 |

每完整邊界一份合法見證，在完整消元契約下足以求一解，但不保留全解；目前只做審核對照。
任意截斷完整邊界列不安全：四葉星232列即使只刪一列，也可被外側固定色選中而錯判。
不把80.04%流程、29.41%索引、12.82%prefix與28.89%map體積相乘成總收益。

## 主引擎分區：局部較小不等於整體較便宜

下列全部是**完整表消元的選點排程**，與後面的按需接口圈區分開。
靜態分隔先排內部、最後排分隔點；當前全部因子仍須共同處理，不能略掉跨區限制。

| `--partition` | 適用與代價估計 | 固定40例歷史結果／主要特例 |
| --- | --- | --- |
| `none` | 每步全圖動態min-fill；基準。 | 27可解／13無解／0超限，10,433,208 checks，最大嘗試邊界10。 |
| `components` | 原圖連通分量分組，區內min-fill。 | 本批與`none`同checks；沒有憑分組就省工。 |
| `articulation` | 平衡原圖割點，內部先消；有小割點時可能有利。 | 6例超限、39,722,791 checks、最大嘗試邊界93；等色分支30層相容例少約4.5%，12層相容鏈反而超限。 |
| `bfs` | 原圖完整BFS層作平衡分隔；希望分隔點少。 | 15例超限、82,977,664 checks、最大嘗試邊界105；偶輪控制少8.8%，整批退步。 |
| `adaptive` | 保持當前全圖最小結構級別，優先目前工作區，再比枚舉估計A。 | 全完成，10,391,990 checks；當輪12.46→13.27秒。 |
| `information` | 同結構級別先比A，再優先目前工作區。 | 全完成，10,390,284 checks，少0.41%；當輪12.46→12.80秒。12層相容鏈checks仍增5.02%。 |
| `message` | 先比因子列數、域乘積、因子數構成的W，再比結構級別。 | 全完成，10,751,514 checks，增3.05%；60點相容三角化例增19.03%，另100點控制少8.05%。 |

靜態門檻12只是停止細分條件，不是邊界或樹寬上限；動態門檻12限制工作區成員數，
亦不限制接口。A／W不涵蓋後續傳播、未來因子與全部排程CPU，局部便宜不能推整次便宜。
詳見[靜態分區](four_color_partition.md)與[當前訊息分區](four_color_information_partition.md)；預設保留`none`。

## 後續傳播：scan、delta與support

| 模式 | 省什麼／保存什麼 | 有利條件及增加成本 | 同範圍歷史比較 |
| --- | --- | --- | --- |
| `scan` | 依既有順序掃接口配對，revision快取可略過已完成查詢。 | 管理簡單，但反覆訪問大量未變配對；仍為預設。 | 原排程40例10,433,208 checks，當輪12.86秒。 |
| `delta` | 變動配對佇列、單側完整支援重用、整表接口引用與局部域簽章。 | 重複傳播多時有利；相依索引、佇列管理仍花CPU／RAM。沒有將全部域／環改成事件驅動。 | 同輪原排程10,265,841 checks、11.71秒；information 13.35→12.09秒。12／13例各自牆鐘仍增。見[delta](four_color_delta_propagation.md)。 |
| `support` | 在delta上保存完整S，以失去最後支援的完整接口tuple刪對側原列。 | 對側私有延伸多、失效支援少時有利；目前仍重建投影，訊息與差量成本可能高於收益。 | 另一輪原排程delta 10.710→support 10.798秒；接口checks增2.25%，information增2.14%。見[支援流失](four_color_support_loss.md)。 |

support刻意控制有16份接口支援、右側65,536列：只流失1份時，delta／support更新checks
為61,518／4,177；流失15份時反轉為4,104／61,479。這是關係控制，不是圖整次測速。
容量不足時使用完整delta查詢；淘汰加速訊息不等於刪語義關係。delta與support同排程
完成時的完整事件、全部fibres與最後色逐份相等，差別限模式及工作／快取計數。

## 完整表、按需接口與子樹換色

| 表示／求解方式 | 適用目標與精確契約 | 成本與特例 | 可用證據 |
| --- | --- | --- | --- |
| 主引擎完整表及fibres | 需要完整消元證據、所有回填選項；每步保完整桶關係。 | 完整列、證書快照與輸出體積可能先成瓶頸。 | 見[完整消元](four_color_constraints.md)；沒有被下述原型替換。 |

| `solve_local_messages`按需完整查詢 | 一次詢問一份完整接口列；肯定存一份私有見證，否定須窮盡。根成功後共同回填一解。 | 仍會局部試探，最壞問遍接口列；快取未聲稱包含全部fibres。需原邊覆蓋與running intersection。 | 6×7格圖41份不同非根查詢，對照完整支持51,404列；不是CPU／RSS比率。主引擎尚未整合。 |

主引擎的「共同色群歸一化」須認證全部當前因子；按需原型的「子樹換色」針對原邊
異色與整個子樹有效域。兩者可用群與輸出範圍不同，不能以各表獨立換色代替共同框。

## 按需原型的六種圈區次序

這裡只換同一按需求解器的完整消元排列；填補邊表示依賴，不新增原圖異色限制。
共33份條件，幾何法只跑其中30份有原座標者；各方法與min-fill的共同完成集合不同。
下表主要量為非根詢問／答覆傳送的**顏色值總數**，包含重複與否定；不是bytes或RSS。

| 次序 | 適用情境／規劃成本 | 完成／超限 | 同基準共同完成條件的訊息量變化 |
| --- | --- | ---: | ---: |
| `min_fill` | 原型預設，逐步控制填補邊與接口。 | 33／0 | 基準。 |
| `min_degree` | 以填補圖最小度作較便宜的次序對照。 | 32／1 | −3.91%；17例訊息增加。 |
| `geometric_sweep` | 有真座標，軸向正反掃描，以原圖frontier選序。 | 30／0 | −79.32%；13例增加。 |
| `geometric_nested` | 真座標軸線平衡分隔，遞迴先內部再分隔點。 | 28／2 | +71.17%；26例增加。 |
| `bfs_sweep` | 不需座標，兩根各正反距離層，依frontier選四份候選之一。 | 33／0 | −94.23%；20減／3同／10增。 |
| `bfs_nested` | 當前填補圖的完整BFS層平衡切區，葉區min-fill。 | 31／2 | +105.48%；24例增加。 |

BFS掃描全33條件checks含規劃4,018,894→407,630；另設10份確認條件訊息少88.88%。
但9×10普通格圖最大接口12→9，訊息892→1,194，仍增33.86%；接口變窄不保證少問。
7×9隨機對角線確認例也增28.08%。見[圈區報告及全部證據](four_color_region_messages.md)。

**主引擎`--partition bfs`與按需`bfs_sweep`不是同一方案。** 前者靜態先內部再分隔點，
物化完整fibres；後者分層掃描配合按需首見證查詢。兩批圖、預算、checks及輸出不同，
不能用一邊的15份超限否定另一邊，也不能把94.23%訊息減少當作主引擎總加速。

## 部分歷史：table、recipe與mixed

獨立原型保留「已完成精確消元前綴＋剩餘約束＋回填規則」，即使未解剩餘問題，
仍可精確表示全部原解。重建一解須先解剩餘問題；原型的這段窮舉不受建構預算限制。

| 模式 | 保留內容與適用取捨 | 成本／特例 |
| --- | --- | --- |
| `table` | 每完整接口列及全部支援色直接存表；重查成本低。 | 歷史fibres可能很大；仍須剩餘約束。 |
| `recipe` | 引用當時完整bucket因子，對同一接口列重算四個色的全部支援。 | 可省持久fibre表，但須保留引用舊因子，回填多付重算成本；仍計算完整投影。 |
| `mixed` | 偶數索引步存表、奇數步用recipe，證明兩表示可合成。 | 不是已最佳化策略；K₄完整表示3,810 bytes，反比table 3,542更大。 |

四葉星只消中心時，table／recipe整份緊湊JSON為11,519／3,209 bytes，recipe仍保留
232列剩餘投影。不是主引擎RSS、峰值或速度比較。1,144份條件加預算中斷逐份核對，
合計2,231,451次成員判定相等；尚未接入主求解器，見[部分歷史](four_color_partial_history.md)。

## 實際選擇建議與停止點

| 需求／觀察 | 建議起點 | 應同時檢查 |
| --- | --- | --- |
| 主要是一份合法染色 | 先以DSATUR＋強迫＋回退作時間基準。 | 是否常走大量回退；與完整消元比較時固定原圖／固定色，別比不同checks單位。 |
| 要完整fibres及最後共同回填 | 完整消元；先用`none`，依需求加推理。 | 工作上限、完整證書列上限、寬接口及序列化成本分開看。 |
| 多次重查相同完整接口 | 試RAM索引；與prefix、delta各作單獨對照。 | 快取命中／失效、整體牆鐘與RSS；快判否控制保留。 |
| 常見指定奇環／九點構型 | 啟用相應具名推理或有界搜尋。 | 提早判否是否足以抵銷找型與後續交集；無命中時成本也要算。 |
| 打算改分區 | 以`none`對照`information`，保留相容鏈與寬接口反控制。 | 不因某一步A／W較小就推定整次較省；不直接將靜態BFS設成通用起點。 |
| 接口很大、只需一解 | 可試按需原型；格圖／三角格比較`min_fill`與`bfs_sweep`。 | 規劃、重複與否定查詢、回填都計費；保留10份退步，不能只選展示例。 |
| 希望少存歷史但仍表示全解 | 用部分歷史原型檢驗table／recipe及剩餘問題。 | 舊因子引用、回填重算與剩餘求解；不能僅看fibre表省了幾列。 |

本輪是整理、同版本核對與可檢驗的選擇依據，沒有自動挑贏家、調參或改預設。
一般加速、固定接口寬度、完整Python形式化驗證與平面四色存在性仍未由這些比較建立；
Lean的關係語義／支援流失等價式不涵蓋Python排程、快取與效能。
目前研究停止點仍以[四色導覽](../four_color_guide.md)及各權威報告為準。
