2026-10-25。接續[子構造約束與消元回填](four_color_constraints.md)。
先辨識原圖中的無弦五環，由環結構推導或查詢完整五點色組，再把候選限制送回既有求解器；

## 使用

```bash
python3 scripts/four_color_lab.py c5-demo
python3 scripts/four_color_lab.py c5-scan graph.json --local
python3 scripts/four_color_lab.py solve graph.json --engine constraints --c5-local --json result.json --html replay.html
# 若需要一般五環搜尋，再用完整模式：
python3 scripts/four_color_lab.py c5-scan graph.json
python3 scripts/four_color_lab.py solve graph.json --engine constraints --c5 --json result.json --html replay.html
# 同一圖改用原 240 列索引：
python3 scripts/four_color_lab.py solve graph.json --engine constraints --c5 --c5-method table --json table.json
```

播放器提供五張圖各自不查 C₅／完整找環／局部找環的十五份結果；預設選擇
`c5_two_color_conflict` 的局部模式，可跳到衝突，
選擇 `c5_forced_exit` 可跳到查表，查看唯一候選色產生後仍未寫色的狀態。
表格保留原頂點循環次序，顯示目前合法列數及前六列預覽；完整基本表另存 JSON。
畫面使用色號 1–4，JSON 與 Python 使用 0–3。

## 局部模式：每個中心只看一次

依「先快速抓可用五環」的目標，`--c5-local` 做一輪頂點掃描：

1. 每個中心頂點檢查一次；只處理恰有五個鄰點的中心。
2. 核對這五個鄰點的誘導子圖是否為 C₅，再沿它們的原邊走一圈取得順序。
3. 同一環被不同中心找到時去重，登記找到它的中心，再送入所選的結構推導器或 240 列查表器。

這裡的「繞圈」由原邊決定循環次序。沒有幾何嵌入時，不宣稱選定方向就是畫面上的順時針；
兩種推導都使用同一有序循環與字面色框。每個合格中心的局部圖只有五點，檢查工作固定而小，
不必先建立平面嵌入，也不必從每個點向外展開所有長度五路徑。

五角雙錐的兩個五度中心會找到同一個環；固定中心色後，仍能在消元與回寫之前查出兩色奇環矛盾。
裸 C₅ 本身沒有五度中心，這個方法會略過它；中心度數大於五的環也不在本次局部規則內。
少加一些傳播器只影響推導效率，原邊約束和完整消元求解仍保留。

局部模式的 `steps` 是已檢查的中心數，原圖準備工作不另計。
`local_scan_complete=true` 只表示這一輪中心掃描完成；`complete=false` 明確保留「未宣稱找齊原圖 C₅」。
只有預算或收集上限造成提前停止時，才標示 `truncated=true`；兩種原因在畫面分開顯示。
完整模式 `--c5` 仍保留，兩種模式不能在同一命令中同時指定。

同一批圖各跑五次，完整與局部掃描的中位時間如下；兩者涵蓋範圍不同，局部模式是有意少找：

| 同批樣本 | 局部／完整環數 | 完整位元搜尋 | 局部一輪掃描 | 掃描時間比 |
| --- | ---: | ---: | ---: | ---: |
| 100 張 × 30 點 | 379／2,319 | 18.59 ms | 8.25 ms | 2.25 倍 |
| 10 張 × 100 點 | 141／712 | 11.37 ms | 2.80 ms | 4.07 倍 |
| 5 張 × 300 點 | 222／982 | 19.84 ms | 4.72 ms | 4.20 倍 |

合計 115 張圖中 **110 張找到至少一個可用局部五環**，共 **742／4,013 個環**。
全部局部結果皆逐一核對是原圖無弦五環，且屬完整搜尋的結果；每份找到環的中心也另核對。
這些是找環時間與涵蓋率，沒有把它們當成整體求解時間或所有候選色的額外縮限量。
資料與重播命令見下方[找環比較](../../../artifacts/four_color_c5/scan-experiment.json)。

### 每點並行的取捨

每個中心的檢查彼此獨立，可以分工，最後合併並去重。
不過這個局部規則每點的工作很小；目前使用單輪掃描，避免建立程序和傳送圖資料的成本。
[探索性並行原型](../../../artifacts/four_color_c5/parallel-prototype.json) 曾比較完整搜尋的分工：
100 張 30 點圖，序列約 18.45 ms；重用程序池卻把每張小圖再拆成頂點任務，約 100.22 ms；
改為在重用的程序池中分配不同圖，約 7.46 ms。一次小圖的程序啟動測試約 62 ms。
這份原型沒有與正式比較相同的來源雜湊保管強度，只用來說明任務粒度與啟動成本；
正式局部求解器沒有啟用多程序，也沒有對使用者宣稱其平行加速倍數。

## 查表模式的表中有什麼

對有序五環 `(v₀,v₁,v₂,v₃,v₄)`，表的每列是一個完整字面色組，滿足
`cᵢ ≠ cᵢ₊₁`，下標模 5。四色共有 **240 列**。
若只按整體換色合併、保留五個位置，恰有 **10 個等色型**，每型 24 列：

```text
01012  01021  01023  01201  01202
01203  01212  01213  01231  01232
```

這十型是同一張表的分類，查詢時使用全部字面色組。沒有把五個位置排序，
也沒有對不同約束各自換色後當成相容。

設每點目前候選域為 Dᵢ，查詢的是完整共同關係：

```text
R(D₀,…,D₄) = { c ∈ C5_ROWS : 對每個 i，cᵢ ∈ Dᵢ }
```

索引把 240 列編成一個 240-bit 集合，預先記錄每個位置、每個候選域所允許的列。
一次查詢做五次集合交集，接著取得各位置的支援色與合法列數；實作計 **26 次索引操作**。
不需要每次掃描 240 列，也不需要儲存所有 `16⁵` 種候選域組合的答案。
同一五環的候選域沒有改變時跳過重查。

`query_c5((3,3,3,3,3))` 的五個 mask 都表示 `{0,1}`，結果為零列。
`query_c5((7,3,3,3,3))` 則留下兩列：

```text
(2,0,1,0,1)
(2,1,0,1,0)
```

因此第一點必須使用色 2，其餘四點仍各有兩個候選。
這份推論來自五點共同關係；單獨查看每條邊都會看到非空的合法配對。

## 怎樣導入原圖

1. 沿原圖邊搜尋無弦五環，依輸入頂點次序選定起點與方向，去除重複發現的同一環。
2. 既有邊／三角形／K₄ 關係縮限候選域後，查詢仍未消去頂點的五環。
3. 若共同表為空，記錄原五環邊及導致候選縮限的原邊，判定當前固定色條件無延伸。
   若非空，刪除各點沒有共同支援的候選色，再繼續傳播、消元與最後回寫。

C₅ 推導來自原邊條件，所有原約束仍由既有因子保留。
裸環的結構支援與 `table` 模式都只將支援投影送回候選域，不加入新的五點稠密因子；
這部分不額外增加消元接口寬度，跨點相關性由原邊與後續精確消元維持。
`structure` 模式另外將同一原五環兩個共同中心的等色結論，導入為
[`c5_hub_equality` 二元因子](four_color_c5_structure.md)。這會連接消元因子圖中的兩中心，
可能改變消元次序與接口寬度；原輸入圖沒有新增邊，實際成本也沒有必然改善的保證。
只靠 C₅ 候選傳播與已知結構規則仍不足以完成所有判定。

搜尋預設上限為 128 個環、200,000 次候選延伸，可用
`--c5-max-cycles` 與 `--c5-max-scan-steps` 調整。
`c5-scan` 對應使用 `--max-cycles`、`--max-scan-steps`。
達到上限時明確記錄掃描未完成，只省略部分可選傳播器，原求解器仍繼續；
掃描到零個環且未完成，不能解讀為原圖沒有五環。
所選方法的推導操作計入求解器 `max_checks`；圖搜尋另計 `c5_scan_steps`。
推導若中途耗盡預算，會回報 `limit`，不導入部分計算的候選域。

## 找環加速：四點路徑加共同鄰點

目前使用位元鄰接集合。先選一條無弦四點路徑 `s–a–b–c`，最後一點直接查：

```text
d ∈ N(s) ∩ N(c) \ (N(a) ∪ N(b))
```

交集確保最後兩條閉環邊 `c–d`、`d–s` 存在，差集排除兩條可能的弦 `a–d`、`b–d`。
前三步同樣先以位元集合排除已成弦的候選，避免每走到一個鄰點才逐一檢查。
用輸入頂點索引要求 s 最小、a < d，便只保留一個起點與方向。
每個候選集合都由低位元到高位元取出，完整環列表與舊版 DFS 的順序完全相同。
這個方法不要求原圖平面。

計數單位已改為「選入一個候選延伸」，包括最後的閉環點；
原圖正規化、建立位元鄰接表及候選交集不另計步數。
舊版計的是「檢查一個鄰點」，因此不能把兩版步數直接相除當成加速倍數。
新版 JSON 標示 `bitset-induced-path-join-v1` 與步數語義；時間比較包含各自的輸入檢查與建表。
相同數值的步數上限不代表相同工作量；超限仍只表示未完成掃描。

同一張圖在一次求解中只找環一次；後續候選色改變，沿用原環清單並按域快取判斷是否重查表。
若只要先取得部分環，可優先檢查五度點的五個鄰居是否恰為 C₅，或利用已知平面嵌入找五邊面，
但這些捷徑都不能替代一般五環搜尋。現有五角雙錐案例有十個三角面，仍有一個分隔兩側中心的 C₅；
只掃五邊面就會完全漏掉這個衝突。

同圖找環比較執行五次、交替兩版順序，以下為整批完整掃描的中位時間；
生成圖與比對結果不在計時內，輸入正規化與建立鄰接表包含在內：

| 同批樣本 | 找到的環數 | 舊遞迴 DFS | 新位元交集 | 找環加速 |
| --- | ---: | ---: | ---: | ---: |
| 100 張 × 30 點 | 2,319 | 71.42 ms | 18.59 ms | 3.84 倍 |
| 10 張 × 100 點 | 712 | 35.36 ms | 11.37 ms | 3.11 倍 |
| 5 張 × 300 點 | 982 | 62.39 ms | 19.84 ms | 3.15 倍 |

五張 300 點圖都在找到 128 環後停止，兩版各得 640 環、全部標示掃描未完成，

## 看得見的衝突與縮限

本節工作計數是加入已知衝突辨識器前的 C₅ 開／關比較；新預設模式可能由已登記子型先命中，
應用 `--no-conflicts` 區分辨識器的效果，不能把歷史數字當成新預設模式的測速。

`c5_two_color_conflict` 使用七點平面的五角雙錐：兩個不相鄰中心各連到五環的全部頂點。
中心固定為色 3、4 後，環上每點只剩 `{1,2}`，五環的共同表為空。
無固定色的同一張圖能成功四色染色；衝突只否定指定的固定色延伸。

| 案例 | 三角形／K₄ 基準檢查數 | 加 C₅ 檢查數 | C₅ 效果 |
| --- | ---: | ---: | --- |
| 裸五環 | 764 | 790 | 候選域全為四色，沒有可刪除色 |
| 自由五角雙錐 | 9,520 | 9,546 | 成功回填，沒有可刪除色 |
| 固定雙中心衝突 | 406 | 266 | 由 3 次消元後發現，提前至 0 次消元 |
| 移除一條中心到環的邊 | 380 | 382 | 提前刪去 2 個候選，留下 2 個完整色組 |

衝突兩模式均新增零個寫色。移除一條邊的案例會把環上一點強迫為色 3，
但該點仍保持未寫色，直到後續全部消元成功再倒序回填。
提前推導不保證總檢查次數更少，最後一列就是例子。

## 與既有 C₅ 邊界目錄的區別

本次導入的是**裸五環的全部十型**，可由五條原邊直接確認。
專案的 [C₅ 邊界關係 Σ(G)](../../reference/c5/c5_boundary_relations.md) 則描述某個實際 disk 子圖中，
哪些有序五點型能延伸到該子圖內部，通常比裸環限制更強。
僅找到五環，還沒有識別它的內部子圖與外部接點，因此不能任意選一個較窄的 Σ 表套用。
這一版沒有把既有 132 態目錄當作任意原圖的完整來源覆蓋，也不改變該研究的 OPEN 邊界。

若後續導入具體子圖表，須核對同一原子圖、完整接點、有序邊界與字面色框；
