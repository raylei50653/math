# 保留共同條件的交集與原環閉合

2026-10-25。接續[無衝突的保證與缺口](four_color_guarantee_gap.md)。
本輪先記構造及驗證範圍，再量測；優先消除回填前不相容組合，不以速度淘汰推理。

## 構造

取實際原頂點 `h` 與不含 `h` 的有序原簡單環 `C`。對每個當前候選 `h=c`，
只在實際原輻條相鄰的環點排除 `c`，用既有原環前向／後向閉合推導。
這是支援查詢，不決定 `h` 的顏色；環的首點色與中心條件色都在整圈保持一致。

設 `L_c` 是該條件下滿足全部環邊、實際輻條及候選域的完整局部關係。
保留 `L_c` 非空的中心色；每個環點的支援對所有可行 `c` **取聯集**。
互斥條件分支不能取交集。另由每個條件的精確單點支援，導出

```text
P_(h,v) = { (c,d) : 存在同一份 L_c 完整延伸，且 v=d }。
```

另保存每條原環邊的二元投影，以及保留中心色的三元投影
`T_(h,u,v) = {(c,a,b) : 某份同一 L_c 延伸中 u=a,v=b}`。
環邊投影由相同中心條件、相同原環首點色的前向／後向狀態接合，閉合邊也保留；
不把不同條件或不同首點色混合。

這些是字面色框下的完整接口投影，二元最多 16 列、三元最多 64 列。把它們作為必要因子，
交回既有完整共同接口交集；交集再縮表及候選域，會重新觸發原環與條件原環，
直到整個流程穩定。原弦、原環外附件及其他原因子均保留。
不把這些低階投影當作 `L_c` 的完整多點聯合關係，也不以局部非空宣布整圖有解。

## 搜尋及正確性邊界

先在每個活動原中心的實際鄰點誘導子圖中找有界基本環，保存原環次序與原輻條。
不依圖族名稱、預存答案或固定頂點號識別輪圖。候選域／活動點變動可重搜；
預設最多 128 份不同中心／原環，每中心搜尋最多 200,000 步，均計入主工作預算。
搜尋截斷只略過可選必要推理，不作完整覆蓋或無解聲明。
本輪自動搜尋的環點皆與中心有原輻條；純查詢 API 也可處理部分輻條，
但未聲稱自動搜尋涵蓋所有部分輻條構型。

任何原圖完整解的限制都屬於其對應 `L_c`，因此在每個導出接口中都有該完整
解的投影列。聯集支援及整列交集都保留所有完整解，加入這些因子不改變原圖可解性。
所有條件計算、精確計數轉錄及新增列的儲存檢查完成後，才提交該次域及因子變更；
中斷回傳 `limit`，不把部分條件結果當完整支援，也不提前填色。

新接口若已由某張現存完整表保證，就共用既有因子：將該表限制於本次準備提交的
候選域，再依同一有序接口投影；只有完整投影確實包含於新接口時才省略新增。
這是可逐列核對的邏輯蘊含，不是只比較單點域。後續精確消元仍保留此蘊含，
因此不用重複保存同一必要限制。既有接口若已受其他交集縮限，仍保留並更新，
不會因新的較寬查詢而擴回。

主十二點反例應由八次消元提前到零次；另核對九點缺口是否由四次降至零次。
兩份可解控制的六份及九十份完整原邊解全部逐記錄保留；二十四結構例沿用精確
全域接口投影，十二隨機例保留前輪指定見證／窮盡無解參考的界線。
另核對部分原輻條、弦及外接點、非連續頂點號、多可行中心色取聯集、
查詢中斷與零搜尋上限，以及投影確實交回交集傳播。

## 啟用方式

```bash
python3 scripts/four_color_lab.py solve graph.json --engine constraints --intersections --cycles --cycle-contexts --json result.json --html replay.html
uv run --with-requirements requirements.txt python scripts/four_color_cycle_context_experiment.py
```

Python API 使用 `solve_constraints(graph, use_intersections=True, use_cycles=True,
use_cycle_contexts=True)`；新模式須與交集及原環閉合同時啟用。
`cycle_context_max_contexts` 控制保存的不同中心／環上限，
`cycle_context_max_scan_steps` 控制每中心一次鄰域搜尋步數。
所有查詢與接口新增列另受主工作及儲存上限約束。

各自獨立參考，沒有工作超限、事件截斷或全域投影核對省略。

| 同一原構型／指標 | 原交集＋原環 | 加共同條件接口 |
| --- | ---: | ---: |
| 十二點奇輪，矛盾前消元數 | 8 | **0** |
| 九點固定色反例，矛盾前消元數 | 4 | **4** |

| 十三無解例，矛盾前消元合計 | 12 | **4** |

十二點例的中心三色條件分支全部使奇環僅餘同一兩色，完整局部關係為空，
所以不必消元或選定任何中心色就能發現矛盾。九點反例仍需四次消元；
二／三元接口投影尚未保存其全部跨區共同關係，保留為明確未補齊的邊界。

偶六環控制的六份合法解，以及解除中心私有葉固定色控制的九十份合法解，
在兩模式逐份、逐候選域、逐輸入表及完整回填表核對，全部保留。
後者在回填前已推出中心只能用字面色 `3`，仍保持未寫色；其輪圖局部色組為 30，
乘上外側未固定葉的三種延伸才是原圖 90 解，兩個計數不混用。

### 確實使用交集回饋

另保存一份[接口回饋控制](../artifacts/four_color_cycle_contexts/controls/)，
使用實際原環、輻條與固定葉實現候選域，停用三角形模板作隔離。
原環閉合後各點候選完全不變，新接口仍能讓原因子與導出因子的共同接口交集
刪去不相容整列，發生在首次消元以前。十一份完整合法解兩模式全部保留。
這份額外控制不混入四十例統計。

### 重複接口與原型記錄

最終模式共省略 27,763 份已由現存完整因子保證的新接口，僅新增 580 列必要接口。
省略的依據為上文完整表蘊含檢查，沒有只用單點候選猜測冗餘。
先前一律新增接口的[原型](../artifacts/four_color_cycle_contexts/prototype-all-projections-5m/)
保留八十份執行與當輪來源：同一五百萬工作上限下有十四份可解參考例超限，
皆記為尚未判定。最終版本使用同一工作／儲存上限，八十份全部完成；
不把原型超限當無解，也不以本輪結果宣稱一般速度或傳播完備性。

### 驗證界線

完整相關測試 171 項通過，其中新增 20 項，保存[測試紀錄](../artifacts/four_color_cycle_contexts/tests.log)。
包含原邊獨立枚舉的二／三元接口投影、部分輻條、零域、非連續原 ID、
多條件取聯集、交集回饋、多解保留、查詢／接口提交前中斷、零上限與 CLI。
正常／seed-17 的三份輸入、摘要與八十份 gzip 記錄，共 84 檔逐位元組一致；
31 份來源快照與摘要 SHA256 及本輪完成時的程式一致。

二十四結構例保留完整全域投影核對；十二隨機例的十份可解參考仍只核對指定見證，
兩份無解仍沿用凍結原邊窮盡參考。不能把這族擴大為全部解枚舉。
九例條件構型搜尋曾達 128 份上限，普通原環搜尋兩模式各十八例曾省略搜尋；
這些都是有界必要推理，與主工作超限或完整簡單環覆蓋不同。

[瀏覽器核對](../artifacts/four_color_cycle_contexts/browser.json)涵蓋十份代表執行、
60 個關鍵步驟；五個共同條件面板、七個交集面板及十六個原環面板皆通過。
408 份縮限快照均確認未固定點尚未寫色；六份最終染色再逐原邊與固定色驗證。
主反例三個中心色分支皆空、放寬控制的唯一中心候選仍未寫色，以及
接口回饋控制在消元前取交集皆核對完成，無 JavaScript 錯誤。
